# 図書処理状況アプリ 要件

## 1. 目的

Power Automate の作業キューについて、利用者がアップロードした処理の実行状況を確認できるようにする。

主な利用シーンは以下とする。

- 指定したプロジェクトの処理状況を確認する
- 対象フローの待ち・処理中件数を確認する
- 自分が依頼した処理の状態を確認する
- メンテナンスや処理失敗を利用者へ案内する

## 2. 対象範囲

| 区分 | 設計 |
|---|---|
| 状態の保存先 | SharePoint List |
| 利用者向け画面 | Power Apps Canvas App |
| 対象 | Power Automate の作業キュー状態確認 |
| 対象フロー | 6フロー |
| 集計・分析 | 今回は対象外。将来は Power BI を検討 |
| 対象外 | 再実行、技術エラー詳細、Power Automate 実行履歴の完全な表示 |

## 3. データ連携

各 Power Automate フローは、キュー項目の状態変化時に SharePoint List へ状態を投影する。

### 共通列

- `flow_type`
- `status`
- `requested_by_upn`
- `project_id`
- `queued_at`
- `updated_at`
- `queue_id`
- `display_message`

### フロー固有列

フローごとに、利用者が対象処理を識別するための情報を保持する。

例：

- 図書番号
- 案件名
- アップロードファイル名
- フォルダ名
- 受付番号

### 利用者判定

- `requested_by_upn` は必須とする
- フロー用アカウントが更新するため、SharePoint の作成者・更新者列は利用者判定に使わない
- Power Apps ではログインユーザーの UPN と `requested_by_upn` を照合する

## 4. フロー表示

ホーム画面では、6フローを 3列 × 2行 のカード形式で表示する。

各カードには、業務名とアップロード先フォルダ名を表示する。

| 業務名 | アップロード先 |
|---|---|
| 図書発行・返却 | `503_図書発行・返却用` |
| ベンダー図書リスト登録 | `505_ベンダー図書リスト_JDMS登録用` |
| 社内レビュー依頼 | `504_発行準備用` |
| MOM登録 | `506_MOM_Corret登録用` |
| 協力会社図書提出 | `協力会社図書提出用` |
| 日記図書提出 | `日記図書提出用` |

フォルダ名と業務名が一致しない場合があるため、フォルダ名は利用者向けの補助情報として表示する。

## 5. 画面構成

画面数は2画面とする。

### 5.1 図書処理状況

利用者が対象プロジェクトと処理を選択するホーム画面。

#### 表示内容

- プロジェクト選択
- 全体稼働状況
  - 処理中件数
  - 待ち件数
  - 対象：全6フロー・全プロジェクト
- 更新ボタン
- 最終更新時刻
- メンテナンス案内バナー
- 「確認したい処理を選択」の見出し
- 6フローのカード

#### 各フローカードの表示内容

- 業務名
- アップロード先フォルダ名
- 待ち件数
- 処理中件数
- メンテナンス中バッジ（該当フローのみ）

#### 件数の対象

各フローカードの待ち・処理中件数は、以下を対象とする。

- 選択中プロジェクト
- 全利用者
- 対象フロー
- 当日分

カードには「全体」と分かる表示を付ける。

### 5.2 ［処理名］の実行状況

選択したフローについて、自分が依頼したキュー項目を確認する画面。

例：

- `社内レビュー依頼の実行状況`
- `図書発行・返却の実行状況`

#### 初期表示条件

- プロジェクト：ホーム画面で選択したプロジェクト
- フロー：ホーム画面で選択したフロー
- 依頼者：ログインユーザー本人
- 期間：今日
- 状態：すべて

#### 表示内容

- パンくず・戻るボタン
- 処理名
- アップロード先フォルダ名
- プロジェクト選択
- 期間切替
  - 今日
  - 過去7日
  - 期間指定
- 依頼者：自分
- 検索
  - 図書番号
  - 案件名
  - ファイル名
- 状態フィルタ
  - すべて
  - 待ち
  - 処理中
  - 完了
  - 失敗
- 並び替え
  - 初期値：最終更新日時（新しい順）
- 更新ボタン
- 最終更新時刻
- 表示件数

#### 一覧の共通表示項目

- 状態
- 案件名
- アップロード内容
- 受付日時
- 最終更新日時
- 受付番号

フローごとに必要な列だけを追加表示する。

#### 一覧の閲覧範囲

- 利用者は自分が依頼したキュー項目のみ閲覧可能
- 他利用者のキュー項目は表示しない
- 運用者・管理者は別権限で必要範囲を閲覧可能とする

## 6. 状態表示

| 内部状態 | 利用者向け表示 |
|---|---|
| Queued | 待ち |
| Running | 処理中 |
| Completed | 完了 |
| Failed | 失敗 |

ホームの全体稼働状況とフローカードには、`待ち` と `処理中` のみ表示する。

`完了` と `失敗` は、フロー別の実行状況一覧で確認できるようにする。

## 7. メンテナンス表示

社内システムなどのメンテナンスにより処理遅延・停止が起こる場合、画面上部にバナーを表示する。

表示例：

> 一部のシステムはメンテナンス中です。処理に時間がかかる場合があります。

特定フローのみが影響を受ける場合は、対象フローカードにも `メンテナンス中` バッジを表示する。

## 8. エラー表示

技術的なエラー内容は利用者に表示しない。

失敗時は、汎用メッセージと受付番号を表示する。

表示例：

> 処理を完了できませんでした。解消しない場合は運用担当へお問い合わせください。  
> 受付番号：Q-20260312-005

エラー原因を正しく判定できない場合も、同じ汎用メッセージを使用する。

## 9. VM状態

VMの起動状態、台数、CPU使用率などの技術的な監視情報は、一般利用者向け画面には表示しない。

利用者向け画面には、処理影響として以下のみを表示する。

- 待ち件数
- 処理中件数
- メンテナンス中
- 処理遅延の案内

VM増設後も、VM単位ではなくキュー全体の状態として表示する。

## 10. 権限

- Power Apps は `requested_by_upn` とログインユーザーのUPNを照合して表示を絞り込む
- SharePoint List 側でも、依頼者・運用者・管理者に応じた閲覧権限を設定する
- 利用者は SharePoint List を直接操作せず、Power Apps を入口とする
- 運用者・管理者のみ、必要に応じて全体のキューを確認できる

## 11. 基本導線

`プロジェクトを選択 → 確認したい処理を選択 → 自分が依頼した処理の状態を確認`
