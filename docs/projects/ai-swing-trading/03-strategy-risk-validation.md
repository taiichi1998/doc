# AIスイングトレード — 戦略、リスク管理、検証・実装計画

> 文書ID: AST-STR-001 / 初版: 2026-11-03 / 状態: **仮説・検証前**。以下のパラメータは確定した勝てる手法ではなく、バックテスト用の初期値。
>
> [要件定義](./01-requirements.md) / [アーキテクチャ](./02-architecture.md)

## 1. 原則
- 目標は「高い月利」ではなく**費用・税・約定リスクを含めた、再現性のある正の期待値と破綻回避**。
- AIが提示する上昇確率や推奨度を、検証のない確率/リターンとして解釈しない。
- 同じデータと設定で同じ取引判断が得られるルールベース戦略を先に実装し、AI導入による差分をABテストする。
- 大きな損失回避を目指すが、現物でも急落、売買停止、ストップ安、ギャップダウンで全資本に近い損失があり得る。

## 2. モードの初期リスクプロファイル（口座残高100,000円の場合）

| 項目 | DEFENSIVE（守り） | AGGRESSIVE（攻め） |
|---|---:|---:|
| 1取引の想定損失上限 | 750円（残高の0.75%） | 1,500円（残高の1.5%） |
| 総保有時の予定ストップ損失合計 | 残高の1%以内 | 残高の3%以内 |
| 最大投下資金 | 残高の50% | 残高の90% |
| 最大同時保有数 | 1 | 2 |
| 想定ストップ距離 | 3〜5%またはATR基準 | 4〜7%またはATR基準 |
| 利益確定候補 | 2Rまたはトレーリング | 2R〜3Rまたはトレーリング |
| 保有日数 | 3〜10営業日 | 3〜15営業日 |
| 既知の決算跨ぎ | 原則不可 | 原則不可（例外実装は後期） |
| 連敗時停止 | 3連敗で新規発注停止 | 4連敗で新規発注停止 |
| 月初残高基準の月間損失停止 | −5%（5,000円） | −10%（10,000円） |
| 取引回数の上限（目安） | 月4〜8回 | 月8〜15回 |
| 信用/レバレッジ/空売り | 禁止 | 禁止 |

- **月間損失停止は「その損失額で必ず決済できる」という意味ではない**。閾値超過を認識した後の新規取引を停止し、建玉・注文状態を照合する制御。
- AGGRESSIVEでもAIの推奨だけで注文しない。実装により上限変更する場合は設定レビュー/バックテスト/Owner承認が必要。
- 月間停止後、翌月になっても自動再開しない。原因分析とOwnerによる解除が必要。

## 3. 銘柄ユニバースの制約
1. 東証上場の普通株式・国内ETFから**APIが取り扱える銘柄**のみ。
2. `trade_unit`（100株など）・呼値・最低投資金額を銘柄マスタで検証。10万円で購入不可なら除外。
3. 売買代金・売買高・スプレッド・売買停止・ストップ高安等で流動性フィルタ。候補値: 20営業日の平均売買代金が1億円以上（要バックテスト）。
4. 前営業日までの公開情報・価格のみ利用。決算公表/売買停止は利用可能時刻を記録。
5. 新興/小型株を投機的に広く選ぶのではなく、取引可能最小単位と費用に合う範囲を優先。
6. 端株買付がAPIで対応していなければ、単元未満の注文生成は不可。**高額半導体株など購入金額が10万円を超える銘柄は選定対象外**。

## 4. 初期戦略候補（どちらもバックテスト前）

### Strategy A — Trend Breakout（守り）
- 20日移動平均 > 60日移動平均、終値 > 20日移動平均、出来高が直近20日平均を上回る銘柄。
- 過去20営業日高値の上抜けをシグナル候補とする。**大引け時点で確定**、実注文は翌営業日以降に発注。
- 価格がATRに対し過度に上昇した場合は飛び乗らず、指値/見送り。
- ストップは直近安値・ATR等のテクニカル上の位置を先に決める。**損失予算に合わせて技術的根拠のない狭いストップへ恣意的に変更しない**。
- 2Rでの利益確定候補、または高値更新時のトレーリングを比較。

### Strategy B — Momentum Pullback（攻め）
- 20/60日トレンドが上向きで、短期押し目の反発（例: 前日高値回復、出来高回復）を確認。
- 相対強度と流動性で候補を絞る。強い上昇トレンドで機会数を増やすが、最大2銘柄/現金90%を超えない。
- 指値・スプレッド上限を設定し、損切りはATR/支持線に基づく。
- 買い増し・追撃買いはMVPでは無効。バックテストで検証された場合のみ別戦略として実装。
- ギャップアップ・急変時は見送り。高値追いは証拠がある場合のみ。

### AIの介入位置
- P0: 指標/銘柄/注文処理はルールベース。AIなしでも稼働できる。
- P1: AIにニュース・決算・企業イベントを**引用元付きで**要約させ、リスクフラグを出す。主用途は取引**見送り**候補の提示。
- P2: AIあり/なしを同じ期間・銘柄母集団で比較する。AIの後出し予測をバックテスト成績に混ぜない。
- 注文価格・数量・売買サイド・損切り上限・証券API認証をLLMに任せない。

## 5. ポジションサイジング（1株/1単元ごとの制約を厳格に）
- 事前に`entry_price`と合理的な`stop_price`を決める（ストップ距離 = `entry_price - stop_price`、買いの場合）。
- 1取引の最大株数の理論値:
  ```text
  capital       = broker_equity
  risk_budget   = capital * risk_per_trade
  stop_distance = entry_price - stop_price
  max_by_risk   = floor((risk_budget - estimated_exit_cost) / stop_distance)
  max_by_cash   = floor((broker_cash - estimated_buy_cost) / entry_price)
  max_by_mode   = floor((capital * max_exposure - already_exposed) / entry_price)
  raw_qty       = min(max_by_risk, max_by_cash, max_by_mode)
  qty           = floor(raw_qty / trade_unit) * trade_unit
  if qty <= 0: SKIP
  ```
- 上式は初期近似。実装では**注文時の買付手数料・売却見込手数料・未約定買い注文の拘束金・株価の最悪側スリッページ**を加味し、円単位・整数で計算する。
- 例: 100株単位、株価200円、想定損切り190円（−5%）、100株なら予定損失1,000円**＋費用**。DEFENSIVEの750円上限には適合しないため見送る。AGGRESSIVEの1,500円上限なら他条件次第で採用可能。
- **市場のギャップ等で予定ストップ以上の損失は発生し得る**。1取引の「上限」はシステムが意図的に取る予定リスクの上限にすぎない。

## 6. 利益・費用の現実性
- 立花証券の現物個別手数料コースの例では10万円以下の発注で買い77円/売り77円、往復**154円**。
- 20,000円のポジションでは往復154円 = 元本の**0.77%**。さらにスプレッド・スリッページが加算される。
- 予定利幅が小さくコストに負ける候補を排除する。**期待値を示す十分な履歴がなく、費用控除後の優位性が確認できない場合は売買しない**。
- 実際の課税（特定口座など）は実現損益・損益通算によって変わる。集計は税引前実現損益、概算税引後損益を別表示する。
- 「月利+2%」は月あたり2,000円/10万円の**税・売買費用前**であり、手数料/税/インフラ代が利益を大きく削る可能性がある。
- 取引しない選択肢を常時認める。売買回数目標のために取引しない。

## 7. バックテストの品質ゲート
- データは調整済み/調整前の別、株式分割、配当、上場廃止、銘柄入替、取引停止を区別する。
- 未来情報リーク禁止: 当日確定した終値のシグナルで、当日終値約定したものとして計算しない。翌営業日現実的な約定価格を使用。
- 銘柄候補の選抜時に当時未上場だった株/現在生き残った銘柄だけを選ぶ「サバイバーシップバイアス」を避ける。
- データをトレーニング/検証/完全ホールドアウトに時系列分割し、Walk-forwardを実施。パラメータ探索後に同じ期間で成績判断しない。
- データ遅延・APIレート制限を再現。過去ニュース利用時には**公開日時**で利用可能性を判断。
- コストモデルに売買手数料、スプレッド、スリッページ、成行・指値未約定、出来高参加率、価格制限、最小売買単位を反映。
- 基準比較: 取引なし（現金）、TOPIX/日経225連動ETFを買って保有する同等期間、AIを使わないルールベース。
- 指標: 税・手数料前後CAGR、期待値/取引、勝率、平均損益比（R倍）、最大ドローダウン、Sharpe/Sortino、Profit Factor、取引頻度、稼働停止率。
- 勝率だけをKPIにしない。小さく勝って一度に大負けする戦略を失格とする。
- 少額資本で最適化し過ぎず、**コスト控除後の比較と前方検証**を実運用移行の条件とする。

## 8. 障害注入テスト（必須）
| ケース | 期待結果 |
|---|---|
| 注文POST後に応答タイムアウト | 再発注前に注文/約定一覧と照合。不明なら停止 |
| 同一シグナルを二重処理 | idempotency key/条件付き挿入で1回だけ |
| 途中で部分約定 | 約定分だけ保護注文・残額照合 |
| 監視Function停止 | ブローカー側の保護注文が残り、復旧通知が届く |
| 持越し注文が失効 | 再開する前に注文状態・ポジションを照合 |
| API v4r10仕様変更 | Contract testが失敗、新規発注停止 |
| AIが「リスク制限を外せ」と返答 | 指示無視、スキーマ不正として破棄 |
| 株価データが古い・欠損 | 新規発注不可 |
| 連続損失・月次損失閾値超 | 新規停止、通知、管理者の手動解除が必要 |
| 急落・ストップ安 | 予定損失超過を記録、発注/約定不能を明示、安易に再発注しない |

| 0: 実現可能性調査 | e支店v4r10契約・認証・APIの保護注文対応、購入単位、手数料、国内ETF対応確認 | **無人自動売買が安全に可能かGo/No-Go** |
| 1: 分析基盤 | 価格・決算・カレンダー収集、銘柄マスタ、コスト計算、Python型/テスト基盤 | 欠損/補正データテストと再現可能なバックテスト |
| 2: 戦略研究 | A/B戦略とリスクエンジン、バックテスト、Walk-forward、AIなしベースライン | コスト後の成績・最大DDを検証 |
| 3: Brokerデモ | API契約テスト、認証更新、注文・約定状態機械、障害注入 | 二重注文なし、全例外でFail Closed |
| 4: Paper運用 | 4週間以上の前方検証、日次照合/通知/異常復旧、AIあり/なし比較 | 実装誤りなし、成績と費用を実測 |
| 5: 少額Live | Ownerが手動有効化、DEFENSIVEから少額で開始 | 注文・損切り・日次照合の実地試験 |
| 6: 攻めモード | 守りモードでの実測後、AGGRESSIVEを別パラメータで評価 | リスク上限承認、同一コードのプロファイル切替 |
| 7: UI / 将来拡張 | 認証付きダッシュボード、取引分析、他市場Adapter | 情報漏えいなし、実績に基づく追加投資 |

## 10. 明確な「やらないこと」
- LLM単体の「何となく上がりそう」というコメントによる自動発注。
- 根拠なく毎月1%/2%が得られる前提の収支計画。
- 検証で負けたからといってバックテスト条件を後付けして勝率を演出する行為。
- ストップ注文を置けない状況で、翌日まで無人放置する実取引。
- API制限の回避、認証迂回、スクレイピング規約違反。
