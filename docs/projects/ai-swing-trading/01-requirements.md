# AIスイングトレード自動売買システム — 要件定義書

> 文書ID: AST-REQ-001 / 状態: 設計ベースライン（実口座接続前の確認事項あり） / 初版: 2026-11-03 / 対象: 個人利用・日本株
>
> 本書はシステム要件の定義であり、収益を保証する投資助言ではない。想定損失の上限は**注文価格での約定保証ではない**。ギャップダウン、ストップ安、取引停止、API障害では設定額を超える損失が発生し得る。

## 1. 目的と背景
- 手元資金 **100,000円**を使用し、保有期間 **3〜15営業日**の現物スイングトレードを定量的に検証し、ルールに従って自動執行する。
- 人間の感情による損切り遅延・ルール逸脱を抑え、AIは**解釈・候補評価・記録分析の補助**に活用する。
- 守り重視（DEFENSIVE）と攻め重視（AGGRESSIVE）の2モードを切替可能とする。ただしどちらも資本保護のハード制御を最優先する。
- 月利+1〜2%は**比較用の希望目標**にとどめ、予測期待収益率・KPI合格条件とはしない。AI利用により超過収益が得られるとは前提しない。

## 2. 対象範囲
| 区分 | 内容 |
|---|---|
| In Scope | 国内上場株式・国内ETF（APIで売買可能な銘柄に限定）、現物取引、ロングのみ、証券API接続、日次市場データ取得、銘柄スクリーニング、シグナル、リスク判定、発注・約定照合、履歴、バックテスト、デモ/ペーパー、通知、緊急停止 |
| Out of Scope (MVP) | 信用・空売り・レバレッジ・先物・FX・暗号資産、秒足のHFT、SNSによる自動売買、生成AIによる任意価格の直接発注、自動資金追加、複数証券口座横断、一般向けサービス提供 |
| 将来拡張 | 米国株ブローカーAdapter、ポートフォリオ最適化、フロントエンド、機械学習モデル。ただし費用/法令/API適格性再審査後 |

## 3. 確定した前提
- 初期投資元本: 100,000円。入金は手動で行い、追加入金を自動実行しない。
- 初期市場: 日本株・国内ETF。NISA利用可否、単元未満株、売買単位は**ブローカー仕様と銘柄マスタで判定**する。
- 立花証券e支店API（2026-11時点 v4r10）を第一候補。無料API/デモ環境は確認済み。ただし**口座利用条件・注文種別/逆指値のAPI対応・認証更新・注文制約は詳細検証前**。
- ブローカーは現物1注文あたり10万円以下で**税込77円（個別手数料コース）**という料金例がある。売買往復なら154円。別コース、各種制度、条件変更により実際の費用は変動する。
- 単元未満株の**API買付は未確認**。標準の100株単位なら株価1,000円超の銘柄を10万円で100株購入できない。銘柄選定では売買単位・買付余力・手数料を最初に除外条件とする。

## 4. ユーザー/システムロール
- Owner: モード選択、初期設定、実取引有効化、緊急停止、予算設定、レポート閲覧を行う。
- Market Data Worker: データ収集・品質確認・過去データの保存を行う。
- Strategy Engine: 決定論的なシグナルを計算する。
- AI Analyst: 構造化された定性評価と説明を生成する。注文権限は持たない。
- Risk Engine: 取引許可の最終ゲートとなる。設定値をAIに変更させない。
- Execution Worker: 許可済み注文を送信し、取引所・証券会社の応答と約定を照合する。

| ID | 優先度 | 要件 | 受入基準 |
|---|---|---|---|
| FR-01 | P0 | 市場休場日・取引時間・売買単位・呼値・銘柄状態を判定する | 祝日・売買停止・購入不可の銘柄で新規注文しない |
| FR-02 | P0 | ブローカーAdapterを独立モジュール化 | Demo/Paper/Liveの切替が注文インターフェースの差し替えだけで済む |
| FR-03 | P0 | データ品質チェック（日時・欠損・調整株価・異常値） | 古い/欠損データ時は新規注文禁止 |
| FR-04 | P0 | 日足中心にランキング/トレンド/流動性シグナルを算出 | シグナル計算は同入力で再現可能、戦略版を記録 |
| FR-05 | P0 | 2モードの設定プロファイル | モードを変えても既存のストップ注文や残ポジション管理を失わない |
| FR-06 | P0 | 損切りと利益確定の閾値、最大保有期間を事前決定 | 新規建て前にエントリー・ストップ・サイズ・出口ルールが確定 |
| FR-07 | P0 | 発注前の買付余力・単位・価格・リスク・売買停止・重複確認 | 違反時はFail Closed（発注しない） |
| FR-08 | P0 | 注文IDによる冪等化、API失敗時の約定照合 | 応答不明時に同注文を盲目的に再送しない |
| FR-09 | P0 | 部分約定・取消・失効・訂正・注文残の状態管理 | ブローカー照合後にのみローカル状態を確定 |
| FR-10 | P0 | 損切りの安全策を優先 | API対応が確認できればブローカー保管の逆指値を優先。不可なら無人の実取引は禁止し、要件を再設計 |
| FR-11 | P0 | 月次損失上限・連敗停止・異常注文遮断 | 閾値超過時は新規発注停止、既存建玉は安全な決済方針へ |
| FR-12 | P0 | Demo/Paper/Liveの完全分離 | 初期設定LIVE=false、認証情報と注文URLも分離 |
| FR-13 | P0 | 取引履歴・AI出力・リスク判定・監査記録 | 全注文にsignal_id、strategy_version、run_id、risk_decisionを関連付け |
| FR-14 | P0 | データ/証券API障害の検知・通知 | APIタイムアウト/認証不正/価格停滞時に新規建て停止＋通知 |
| FR-15 | P0 | 手数料・税・スリッページを含む損益集計 | 実現/含み損益と税込手数料・売買回転率を区別して表示 |
| FR-16 | P0 | バックテスト・Walk-forward・ペーパー運用 | 未来情報漏洩なく同一戦略を再現。過学習検証を記録 |
| FR-17 | P0 | 手動停止・取引再開承認 | KILL_SWITCHは発注前に必ず参照。再開はOwnerの明示操作 |
| FR-18 | P1 | LLMによるニュース/決算サマリー | 外部テキストは信頼しない。出力はJSON Schema検証、説明専用 |

## 6. 損失上限・ハードルール
- **信用取引禁止・借入禁止・自動追加入金禁止・含み損ナンピン禁止**。AIはこの設定を変更できない。
- 全取引で許容損失額、ストップ距離、売買単位、買付余力を満たす最大株数を切り下げ計算。0株なら見送る。
- 損失上限は市場急変時の損失を**保証するものではない**。ギャップや約定不能により上限を超過し得る。
- 実取引は接続先URL固定・口座番号固定・Ownerの有効化が揃った場合のみ許可する。
- 毎日の開始前、注文前、約定後、終了後に余力と建玉をブローカーと照合し、差異があれば新規取引を停止する。
- 異常な値幅、重複送信、時刻ズレ、口座不一致、取引規制、APIエラー率上昇、キー失効でFail Closed。

## 7. 非機能要件
| ID | 要件 | 基準 |
|---|---|---|
| NFR-01 | セキュリティ | TLS、Managed Identity優先、秘密はKey Vault等に配置、ログはトークン/口座情報マスク |
| NFR-02 | 可観測性 | 注文状態・起動・スケジューラ遅延・データ鮮度・損益・異常を監視 |
| NFR-03 | 信頼性 | 保存状態を正とせず、証券側と再同期。重複発注の検出を最優先 |
| NFR-04 | コスト | MVPの**クラウド+LLM固定費目標500円/月、許容上限2,000円/月**。実課金は別途見積/警告 |
| NFR-05 | 保守性 | Python、型検証、単体・結合・契約テスト、IaC(Bicep)、GitHub Actions |
| NFR-06 | 機密 | 本番口座キー、利用者情報、取引ログを公開GitHubへ保存しない |
| NFR-07 | データ保持 | 注文/約定/損益は最低7年を暫定案として設計。法令・個人運用要件確認後に確定 |
| NFR-08 | 外部API | 公式規約・レート制限・データ二次利用制限を守る。Webスクレイピング回避 |
| NFR-09 | 運用 | クラウド障害、キー更新、注文未確定、ストップ注文消失時の復旧手順を文書化 |

## 8. 受入条件・Go/No-Go
- [ ] 対象口座・v4r10でログイン/デモ発注/約定照会/訂正・取消/注文種別を実測済み。
- [ ] APIでの逆指値・注文有効期限・再起動後の保全について確認済み。未対応なら自動実取引No-Go。
- [ ] 100,000円・単元株・手数料・売買単位を含め、実際に購入可能なユニバースが構成できる。
- [ ] バックテストとWalk-forwardで比較ベンチマークに対する**費用控除後**成績を評価済み。優位性なしならライブ移行しない。
- [ ] 少なくとも4週間のペーパー稼働で二重発注0、欠損データ発注0、状態照合100%（異常時停止を含む）。
- [ ] 最小単位での本番試験・キルスイッチ・リカバリ・通知テストを完了。
- [ ] Ownerの明示承認でLIVEを有効化。初期モードはDEFENSIVE。
- [ ] 実取引では保有銘柄に対して常時監視と保護注文を確認可能な運用体制を確保。
