## 1. コストシミュレーション

### 対象

- SKU変更
- 新規リソース追加

### 入力

Power BI内のパラメータ / スライサーを使用する。

主な項目：

- Service / Resource Type
- Region
- SKU
- 台数
- 必要に応じてOS / License等の料金条件

### Resource Type候補

Azure全Resource Typeを固定実装しない。

表示候補：

- 管理対象RGで実際に利用中のResource Type
- 設定ファイル / Bicepで管理する将来採用候補Resource Type

### 表示

- 現在価格
- 変更後価格
- 月額差分
- 年額差分

Retail Prices APIからStorageへ保存済みの価格データを使用し、Power BIから実行時に外部APIを直接呼び出す構成にしない。

## 2. 変更前後比較

### 変更日時

- Azure Activity Logから候補を取得
- 必要時はユーザーが変更日時を手動指定可能

### 比較期間

- デフォルト：変更前7日平均 vs 変更後7日平均
- 切替：変更前30日平均 vs 変更後30日平均

3日比較・1年比較は初期対象外。

### 表示

- 変更前総額
- 変更後総額
- 総額差分
- Resource別差分
- SKU別差分

Activity Logの変更イベントとコストデータを、Resource・日時等で安全に関連付ける。

## 3. 予算超過原因分析

### 比較

- デフォルト：前月比
- 切替：前日比 / 前週比

### 粒度

- Service
- RG
- Resource
- SKU

### 表示

- 増加額
- 増加率
- Service
- RG
- Resource
- SKU

単純な総コスト上位ではなく、比較期間からの **増加額** が大きいものを原因候補とする。

### グラフ

- Waterfallを使用
- 増加要因を全件確認可能にする
- 金額の大きい順を基本とする

## 共通要件

Phase 05と同じ共通フィルター、最終更新日時、金額単位、フィルターリセットの操作感を維持する。

## 対象外

- 独自Forecast
- Tag単位までの予算超過原因追跡
- Project / Tag別の変更前後影響分析
- 3日比較 / 1年比較
- 独自異常検知

## 検証

### シミュレーション

代表SKUについてAzure Retail Prices APIの保存データと表示価格を突合する。

### 変更前後比較

既知の変更日時を使い、7日 / 30日の対象期間と平均値を手計算で検証する。

### 原因分析

サンプル期間でService / RG / Resource / SKUの差分を元データから再計算し、増加額・増加率・並び順を検証する。
