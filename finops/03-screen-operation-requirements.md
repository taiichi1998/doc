# FinOps 画面・運用要件

## ステータス

**完了**

初期Power BIページ構成、主要KPI、グラフ、フィルター、比較方式、コストシミュレーション入力方式、変更前後比較条件まで確定済み。

## 1. Power BIページ構成

用途別にページを分割する。

初期ページ：

1. 経営サマリー
2. コスト分析
3. 削減候補
4. タグ品質
5. コストシミュレーション
6. 変更前後比較
7. 予算超過原因分析

ページを用途別に分けることで、1画面への情報過多を防ぎ、将来拡張しやすい構成とする。

## 2. 共通画面要件

### 共通フィルター

- Subscription
- Resource Group
- Service
- Resource
- SKU
- Department
- ManagedBy
- Repository
- NetworkMode
- NetworkConfigurationStatus
- Owner
- Project
- CostCenter
- Environment
- Tag

管理対象として存在するタグは、原則フィルター可能とする。

### 共通表示

- 最終更新日時
- 対象期間
- 金額単位
- フィルターリセット

主要ページ間では、可能な限り同じフィルター状態を維持する。

### タグ未設定の扱い

- メイン分析では `Other` または `Untagged` として集約
- タグ品質ページから対象リソースを詳細確認

## 3. 経営サマリー

### KPI

- 総コスト
- 予算
- 予算差
- Forecast
- 部門実質負担額
- 想定削減額

### グラフ・一覧

- 月別コスト推移：直近12か月
- Department別コスト
- Project別コスト
- 主なコスト増加要因
- 削減候補カテゴリ別集計

Department / Project / 増加要因等はTop 5やTop 10に制限せず、対象を全件表示する。
一覧は金額の大きい順を基本とする。
件数が多い場合はスクロールまたは表形式で表示する。

### RG社内負担ルール

- 実コスト
- 実質負担額
- 会社負担閾値
- 閾値までの残額
- 閾値超過有無
- 閾値超過RG件数

実コストと実質負担額は分離して表示する。

## 4. コスト分析

### 初期表示

- メイン表示：月次
- 必要に応じて日次表示へ切替可能

### 期間選択

Azure Cost Analysisの操作感を参考にする。

- 今月
- 先月
- 直近7日
- 直近30日
- 直近3か月
- 直近12か月
- 任意期間

### 分析軸

- Subscription
- RG
- Service
- Resource
- SKU
- Tag

### ドリルダウン

`Subscription → RG → Service → Resource → SKU`

### 比較

- 基本比較は前月比のみ
- 比較対象月を選択可能とする

例：

- 2026年7月 vs 2026年6月
- 2026年8月 vs 2026年7月

前年同月比は初期必須としない。

## 5. 削減候補

### 表示対象

- 未使用リソース
- 低利用 / Right Sizing候補
- Reservation / Savings Plan候補

### 一覧表示項目

- 対象リソース
- RG
- 現在コスト
- 推奨内容
- 想定削減額
- 削減率

Reservation / Savings Planでは、1年・3年の削減額・削減率を比較表示する。

### 優先順位

Power BI側で複雑な独自優先度スコアは作成しない。
想定削減額の大きい順を基本表示とする。

## 6. タグ品質

### 必須タグ

FinOps上の主要タグとして以下をすべて必須対象とする。

- Owner
- Project
- CostCenter
- Environment
- Department
- Service

### KPI

- タグ充足率
- タグ不足リソース数
- 不正値リソース数

タグ充足率は上記6タグを基準に算出する。

### グラフ・一覧

- 不足タグ別件数
- RG別タグ不足件数
- 詳細リソース一覧

詳細一覧：

- Resource
- RG
- 不足タグ
- 不正タグ
- Owner

Tag値の妥当性チェックに使用する許可値は、設定値または管理用マスターとして保持する。

## 7. コストシミュレーション

### 対象

- SKU変更
- 新規リソース追加

### 入力方式

Power BI内のパラメータ / スライサーを使用する。

主な選択項目：

- Service / Resource Type
- Region
- SKU
- 台数
- 必要に応じてOS / License等の料金条件

### 対象Resource Type

Azureの全Resource Typeを事前に固定実装する方式にはしない。

- 対象プロジェクト / 管理対象RGで実際に利用中のResource TypeはAzure API等から取得する
- 将来採用候補のResource TypeはBicepまたは設定ファイルで管理する
- Power BIでは上記の対象Resource Typeのみをシミュレーション候補として表示する

これにより、将来の拡張性を維持しつつ、不要なAzureサービスまで実装対象に含めない。

### 表示

- 現在価格
- 変更後価格
- 月額差分
- 年額差分

### 価格取得

- Azure Retail Prices API
- 価格データはStorageへ保存
- Power BIは保存済み価格データを参照
- 価格データ更新：週1回

## 8. 変更前後比較

### 変更日時

- Azure Activity Logから自動取得
- 必要に応じて手動指定可能

Azure DevOps等のCI/CD以外から行われたSKU変更やPortal操作等も対象とする。

### 比較期間

- デフォルト：変更前7日平均 vs 変更後7日平均
- 切替：変更前30日平均 vs 変更後30日平均

3日比較・1年比較は初期対象としない。

### 表示

- 変更前総額
- 変更後総額
- 総額差分
- Resource別差分
- SKU別差分

## 9. 予算超過原因分析

### 基本比較

- デフォルト：前月比
- 切替：前日比 / 前週比

### 分析粒度

- Service
- RG
- Resource
- SKU

### 表示

- 増加額
- 増加率
- Service
- RG
- Resource
- SKU

単純にコスト金額が高いものではなく、比較期間から増加したものを原因候補として上位表示する。

### グラフ

- Waterfallを採用
- 増加要因は全件確認可能とし、金額の大きい順を基本とする

## 10. RG社内負担ルールの画面反映

RG単位・月単位で以下を確認可能にする。

- RG実コスト
- 会社負担閾値
- 閾値までの残額
- 閾値超過有無
- 部門実質負担額

会社負担閾値は設定値として管理し、具体的な金額はドキュメントへ固定しない。

## 11. 更新・障害時運用

- Cost Management Export：日次
- Power BI更新：日次
- 価格データ更新：週1回
- 必要時はPower BIを手動更新可能
- データ更新失敗時も前回成功データを表示
- 最終更新日時を画面上に表示

## 12. アクセス運用

- 部門内ユーザーは全対象RGを閲覧可能
- 初期RLSは不要
